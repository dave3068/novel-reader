# Novel Reader V1 实际应用开发方案（TXT 版）

> 文档状态：V1 开发基线方案  
> 编制时间：2026-09-12  
> 依据文档：`docs/novel-reader-solution.md`  
> 技术验证依据：`docs/ui-selection/desktop.md`、`docs/ui-selection/android.md`、`experiments/ui-selection/report/env-setup-notes.md`  
> V1 目标：桌面端 Rust + Slint、Android 原生 UI + Rust 共享阅读核心，首个可用版本只支持普通 TXT 文件

---

## 1. 结论摘要

本项目不再继续以“候选 UI 框架比较”作为下一阶段目标，而是进入正式应用开发。V1 采用以下架构：

```text
┌──────────────────────────┐       ┌─────────────────────────────┐
│ Windows / Linux           │       │ Android 12+                 │
│ Rust 应用层               │       │ Kotlin + Jetpack Compose   │
│ Slint UI                  │       │ Android 生命周期/SAF/返回   │
│ 原生桌面文件选择          │       │                             │
└────────────┬─────────────┘       └──────────────┬──────────────┘
             │ 直接 Rust API                       │ JNI + 稳定 C ABI
             └────────────────┬────────────────────┘
                              ▼
                 ┌─────────────────────────┐
                 │ Rust reading-core       │
                 │ TXT 数据源与编码        │
                 │ 章节索引与位置语义       │
                 │ 排版参数与分页协调       │
                 │ 进度、书签、错误模型     │
                 │ SQLite 仓储接口          │
                 └────────────┬────────────┘
                              ▼
                 ┌─────────────────────────┐
                 │ SQLite + 本地缓存        │
                 │ 元数据/索引/进度         │
                 │ 不保存完整正文           │
                 └─────────────────────────┘
```

### 1.1 V1 的产品定义

V1 是“本地 TXT 小说阅读器”，不是通用电子书平台。首个版本应完成从导入 TXT、建立书籍记录、打开正文、整页翻阅、恢复进度到重新关联失效文件的完整闭环。

V1 只允许一种内容格式：

- 普通 `.txt` 文件；
- 不实现 ZIP，即使 ZIP 内包含 TXT 也不接受；
- 不实现 EPUB、MOBI、PDF、在线内容或同步服务。

### 1.2 现有技术验证给出的决策

| 项目 | 当前结论 | 对正式开发的含义 |
|---|---|---|
| 桌面 Rust + Slint | Linux X11、Release、中文显示、分页和重排已验证 | 作为 Windows/Linux 桌面正式 UI 基线 |
| Android Kotlin + Compose | APK 构建、JNI 链接、JVM 单测、真机手动操作路径已验证 | 作为 Android 正式 UI 基线；补齐自动化和生命周期测试 |
| Rust 共享核心 | 有限窗口、UTF-8 边界、位置、锚点、分页契约和测试已验证 | 迁移为正式 crate，禁止 Kotlin/Slint 重复实现阅读业务 |
| Android SAF | 真机手动打开并显示 TXT 已验证 | 正式版保存持久 URI 权限，不能只保存显示名称 |
| 中文分页 | 桌面及 Android 原型已处理尺寸、行高、字符间距和末行裁切问题 | 正式版必须固定“测量口径 = 渲染口径”的契约 |
| Android 自动化完整度 | 旋转、后台恢复、JNI 取消尚未完整自动验收 | 不作为已完成能力宣称，列入 V1 发布门禁 |
| ZIP/完整索引/正式数据库 | 原型范围外 | V1 先不实现，接口保留扩展点 |

原型目录 `experiments/ui-selection/` 只作为验证证据和迁移参考，不直接作为正式应用目录继续堆叠功能。

## 2. V1 范围与明确排除项

### 2.1 V1 必须实现

#### 书籍管理

1. 从桌面文件选择器或 Android 系统文件选择器导入 TXT。
2. 保存书籍名称、来源标识、文件大小、修改时间/文档信息和文件指纹。
3. 书架显示书名、阅读进度、最近打开时间和文件状态。
4. 支持删除书架记录，但不删除原始 TXT。
5. 原文件不可访问时保留记录、进度和书签，并允许重新关联。
6. 书名支持用户手动修改；默认使用去扩展名后的文件名。
7. 书架搜索仅搜索显示书名和原始文件名。

#### TXT 读取与解析

1. 按有限窗口读取，禁止把全文一次性读入内存。
2. 支持 UTF-8、UTF-8 BOM、UTF-16 LE、UTF-16 BE、GB18030、GBK/CP936、Big5。
3. 自动识别编码，并显示识别结果；用户可以手动切换编码。
4. 编码切换后使章节和分页索引失效，但不修改原文件。
5. 统一处理 LF、CRLF、混合换行、空行、超长段落和 UTF-8 多字节边界。
6. 后台扫描常见中文章节标题并建立章节索引。
7. 首次打开优先展示当前位置页面，章节完整扫描不得阻塞首屏。

#### 阅读

1. 整页翻页，不实现连续滚动。
2. 上一页、下一页。
3. 章节目录与章节跳转。
4. 保存并恢复阅读位置。
5. 动态显示当前页序号；完整分页完成前显示“计算中”，不得伪造准确总页数。
6. 根据窗口尺寸、屏幕方向、字号和排版设置重新分页。
7. 书签的新增、删除、重命名和跳转；书签以内容位置为准。
8. 桌面支持鼠标、键盘；Android 支持左右区域点击和系统返回。

#### 全局阅读设置

1. 字体族；
2. 字号；
3. 行距；
4. 段间距；
5. 首行缩进；
6. 阅读区边距；
7. 明亮/暗黑模式及基础护眼配色；
8. 手势/按钮翻页模式；
9. 默认编码及自动识别策略。

V1 不要求实现背景图片。背景图片属于会增加缓存、许可、功耗和排版验收成本的增强项，移至 V1.1 或后续版本。

### 2.2 V1 明确不实现

| 项目 | 处理方式 |
|---|---|
| ZIP 书籍 | 不导入、不扫描、不解压；V1.1 再实现 |
| EPUB/MOBI/PDF | 不实现 |
| 在线书源、账号、同步 | 不实现，应用默认无网络依赖 |
| 正文全文搜索 | 不实现；只搜索书名和文件名 |
| 连续滚动 | 只保留枚举扩展点，不实现 |
| 书签笔记 | 只支持名称，不支持正文批注 |
| 精确阅读时长统计 | 不实现 |
| 原文件外部修改自动重建 | 只检测并提示，用户手动触发重建 |
| 删除用户原始文件 | 永远不由应用执行 |
| 背景图片 | V1 不实现 |
| 每本书独立阅读设置 | V1 采用全局设置；数据结构预留书籍覆盖配置 |

### 2.3 V1 发布分层

为避免“所有功能一次性完成”导致无法验收，正式开发分为三个可运行增量：

- **V1.0-alpha：单 TXT 阅读闭环**：导入一个 TXT、打开、分页、翻页、基础设置、保存恢复位置。
- **V1.0-beta：可管理的 TXT 书架**：多书、搜索、书签、章节索引、失效文件重关联、缓存清理。
- **V1.0：可发布 TXT 版本**：三平台发布物、兼容性回归、生命周期回归、性能和许可证门禁全部通过。

三个版本均不得引入 ZIP 或其他电子书格式。

## 3. 平台与工具链基线

### 3.1 目标平台

| 平台 | V1 支持目标 | 首发策略 |
|---|---|---|
| Android | Android 12+（API 31+） | ARM64（`arm64-v8a`）首发；x86_64 仅用于模拟器/调试 |
| Linux | 项目选定的主流 LTS，首个开发基线为 X11 + glibc 2.28 | 先验证 X11，再补 Wayland |
| Windows | Windows 10/11，x86_64 | 在发布前建立独立 CI/实机构建门禁 |

Android 首发是否加入 32 位 ARM 不在 V1 第一开发循环内；若需要，必须增加独立 ABI 构建、安装包和内存测试，不允许顺手加入而不测。

### 3.2 已知环境基线

- Rust：1.98.0；
- Slint：1.17.1；
- Android：JDK 17、compileSdk 36、targetSdk 36、minSdk 31；
- Android NDK：27.3.13750724；
- Android 构建：Gradle 8.11.1 + AGP 8.10.1 + Kotlin/Compose 2.0.21 的验证组合；
- Linux Slint 编译必须先加载 `/opt/dev-tools/slint-libs/slint-env.sh`；
- Android JNI 不依赖 CMake，Rust 静态库通过脚本链接为自包含 `libnr_jni.so`；
- Release 包必须剥离符号，Debug 体积不能作为产品指标。

正式工程应把实际采用的版本写入根目录版本清单和锁定文件。验证目录中的版本只作为当前可复现基线，不以“探针能构建”代替正式工程门禁。

### 4.1 迁移原则

1. 先迁移共享核心的领域语义和测试，再迁移 UI。
2. 不把 `experiments/ui-selection/shared/rust-reading-core` 原样改成产品库；应删除模拟书库、验证专用指标和合成数据依赖，再补正式数据源和存储接口。
3. 试验用 `SyntheticTextSource` 可以保留为测试夹具，但不得成为正式书籍来源。
4. 任何从探针迁移的行为都必须有产品测试或契约测试覆盖。
5. 原型中的 `ExternalTextSource` 只是坐标空间占位；正式 Android 版本必须完成真实 SAF 窗口读取，不得保留返回空正文的占位实现。

## 5. 分层职责与边界

### 5.1 Rust 共享核心负责什么

Rust 负责所有跨平台且需要保持一致的阅读语义：

- `Book`、`BookSource`、`Chapter`、`ContentPosition`、`Bookmark`、`ReaderSettings`；
- TXT 数据源抽象和有限窗口读取；
- 编码识别结果、编码覆盖和索引版本；
- 章节识别规则与章节位置；
- 页边界、锚点、UTF-8 合法边界和位置恢复；
- 排版签名、布局失效和分页缓存规则；
- 进度/书签的内容位置语义；
- 文件指纹、来源失效状态和重新关联校验；
- SQLite 仓储接口及迁移；
- 错误码、取消语义和可观测事件；
- 不依赖 UI 的单元测试、属性测试和跨端契约测试。

### 5.2 桌面 Rust + Slint 负责什么

- Slint 界面、交互状态投影和窗口生命周期；
- 桌面文件选择器；
- 路径权限和文件系统错误转换；
- 调用 Rust 直接 API，不经过 JNI；
- 使用与可见 `Text` 完全一致的排版参数计算页面；
- 鼠标、键盘、窗口调整、高 DPI 和系统主题适配；
- 把后台任务结果切回 Slint UI 线程；
- Windows/Linux 发布目录和启动器。

桌面层禁止复制编码识别、章节识别、正文分页和位置恢复算法。Slint 只负责最终可见内容的渲染；排版结果必须回报页末内容位置。

### 5.3 Android Kotlin + Compose 负责什么

- Compose 页面和 Android 导航；
- `Activity`、ViewModel、配置变更和生命周期；
- `OpenDocument`/SAF、持久 URI 权限和重新关联；
- Android 系统返回、状态栏、edge-to-edge、触摸手势和无障碍语义；
- Android 字体测量/文本布局和页末 UTF-8 字节偏移回报；
- JNI 参数编解码、线程切换和 UI 状态发布；
- 需要随机访问时为 Rust 提供有限字节窗口，或把非随机数据源复制到应用私有缓存；
- Android 打包、ABI 选择、签名和真机测试。

Kotlin 不得实现第二套章节扫描、位置校验、页边界有效性、阅读进度规则或书签规则。多个挂起入口修改阅读状态必须经同一 `Mutex` 或等价串行化机制；重排请求必须合并，避免字号滑动产生几十个并发重排。

### 5.4 平台差异允许存在的范围

允许差异：

- 文件选择器外观和权限流程；
- 桌面鼠标/键盘与 Android 手势；
- 两端字体测量结果和每页字数；
- 系统栏、返回导航和无障碍实现细节；
- UI 布局遵循各平台使用习惯。

不允许差异：

- 内容位置的含义；
- UTF-8 字节边界规则；
- 书签和进度保存规则；
- 文件失效判定；
- 编码选择语义；
- 页面不能丢字、重字或重复消费的契约；
- 清理缓存不得删除原文件和用户元数据的安全规则。

## 6. TXT 数据源与内容位置设计

### 6.1 数据源模型

```text
TextSource
├── DesktopPathSource       # 桌面文件路径，Rust seek + bounded read
└── AndroidDocumentSource   # Android 持久 URI，平台提供 bounded read
```

数据源必须提供：

```text
metadata() -> size, modified_hint, display_name, source_identity
read_at(offset, length <= MAX_WINDOW) -> raw bytes
can_random_access() -> bool
```

约束：

- V1 单次窗口默认 64 KiB，硬上限 256 KiB；
- 正文缓存只保留当前页、相邻页和索引任务需要的有限窗口；
- 永久位置保存原始字节偏移，不保存临时字符串下标；
- 读取窗口边界自动修正到合法字符边界；
- 任何平台都不得通过一次 FFI 调用返回整本正文。

### 6.2 Android SAF 实现策略

1. 使用 `ActivityResultContracts.OpenDocument`，过滤 `text/plain`，同时允许用户选择无 MIME 标注但扩展名为 `.txt` 的文件。
2. 调用 `takePersistableUriPermission`，保存 URI 字符串、显示名称和权限状态。
3. 读取 `OpenableColumns.SIZE`；若大小不可得，则通过有限方式探测，不能假设为零。
4. 首选通过 `ContentResolver` 的可定位通道按偏移读取窗口。
5. 若提供者不支持可靠随机访问，则复制到应用私有缓存文件，再以本地文件方式分页；复制过程可取消并显示进度。
6. 重新打开时先校验权限和文件指纹；权限失效进入“需要重新关联”，不删除书籍记录。
7. 旋转和后台切换期间不得持有失效的 Activity 引用；文件读取任务只持有可取消的应用级数据源对象。

正式版应优先完成“真实平台字节窗口适配器”，而不是继续扩大 JNI 方法数量。若采用 Kotlin 侧读取窗口，则 Rust 只接收窗口字节和坐标信息；若改为 Rust 侧调用平台回调，则必须补充回调线程、异常跨边界和对象生命周期契约测试。

### 6.3 文件指纹

V1 建议使用以下组合生成来源指纹：

- 文件大小；
- 文件头部、中部、尾部有限抽样哈希；
- 桌面路径或 Android URI；
- 可获得的修改时间/文档版本提示。

指纹用于提示“可能是原书”，不能单独作为安全身份认证。文件内容明显变化时，不自动覆盖旧索引；标记为“需要手动重建”。

### 6.4 统一内容位置

```text
ContentPosition {
    book_id
    content_unit_id       # V1 普通 TXT 固定为一个单元
    chapter_index
    original_byte_offset
    nearby_text_fingerprint
}
```

V1 普通 TXT 只对应一个内容单元。章节是该内容单元中的区间，不把章节编号当作唯一恢复位置。动态页码只属于当前排版签名，不能作为进度和书签的唯一依据。

## 7. 编码与章节索引

### 7.1 编码识别流程

```text
读取有限头部
  ↓
检查 UTF-8/UTF-16 BOM
  ↓
无 BOM 时验证 UTF-8
  ↓
UTF-8 不可信时对 GB18030/GBK/Big5 统计评分
  ↓
保存 encoding + confidence + detector_version
  ↓
低可信度时提示用户确认
```

编码检测不得扫描整个 GB 级文件。默认检测窗口为文件头部有限窗口，必要时从头部、主体抽样和尾部抽样构造评分；具体窗口大小在实现阶段通过测试数据确定。

编码记录至少包含：

```text
encoding
confidence
user_override
encoding_detector_version
content_index_version
```

用户切换编码时：

1. 保留原始文件；
2. 保存用户指定编码；
3. 清除该书的章节索引和分页索引；
4. 使用原始字节位置附近的锚点尝试恢复；
5. 恢复失败时回到最近可确认的章节开头，并明确提示。

### 7.2 章节规则

V1 先实现中文小说中高频且可测试的规则：

- `第一章`、`第1章`、`第001章`；
- `第一卷`、`卷一`；
- `楔子`、`序章`、`前言`、`后记`、`尾声`；
- `Chapter 1` 等英文标题；
- 独立数字标题仅在满足长度、上下文和相邻章节条件时采纳。

章节记录：

```text

book_id

start_byte
end_byte
rule_id
index_version
```

章节识别是启发式结果。没有识别到章节时，必须生成一个“全文”虚拟章节，保证文件仍可阅读。章节扫描任务可取消、可恢复并增量写入数据库。

## 8. 排版与分页方案

### 8.1 分页职责

共享 Rust 核心不负责最终字形光栅，但负责：

- 页面起止位置的业务语义；
- 页面边界合法性校验；
- 排版签名和缓存失效；
- 锚点生成与附近位置恢复；
- 端侧排版结果提交后的连续性校验。

桌面和 Android 使用各自平台文本测量能力：

- 桌面：Slint 可见文本渲染参数和共享分页协调器；
- Android：Compose/公开 Android 文本布局 API，必要时局部使用 `StaticLayout` 等公开 API。

### 8.2 排版签名

排版签名至少包含：

```text
viewport_width
viewport_height
screen_orientation
font_family
font_weight
font_size
line_spacing
paragraph_spacing
first_line_indent
margin_x
margin_y
renderer_layout_version
platform_font_fingerprint
```

任何字段变化都必须：

1. 生成新签名；
2. 使旧页面边界失效；
3. 以当前 `ContentPosition` 或锚点附近位置重新排版；
4. 合并连续设置变更，只保留最终配置；
5. 旧页面未替换前不向用户展示“新页码”与“旧正文”的混合状态。

### 8.3 必须遵守的跨端排版契约

1. Rust 计算的窗口单位与 UI 渲染单位必须一致；Android 统一使用像素参与测量，再按 density 转换为 Compose 显示值。
2. Compose 正文字体必须显式设置 `letterSpacing = 0.sp` 或与测量 API 完全一致的值，不能依赖 Material 默认字距。
3. 测量得到的实际行高必须回传给渲染端；不能一边用 `StaticLayout` 测量、一边用带默认 `lineHeight`/`letterSpacing` 的 Material 文本渲染。
4. 桌面 Slint 的 `Text` 不自动叠加段距和首行缩进时，Rust 排版配置也必须置零，除非 UI 同步实现了同样的效果。
5. 正文区域尺寸必须在窗口映射/布局完成后取得，不能用事件循环启动前的 0×0 尺寸排版。
6. 每页结束位置必须位于合法 UTF-8 字符边界，不能落在代理对、组合字符或多字节序列中间。
7. 小字号、末行和超长行必须预留安全余量，宁可少排一行，不允许裁切半个字或溢出滚动。

### 8.4 翻页与预读

- 当前页 + 前一页边界 + 后三页预读作为初始缓存策略；
- 缓存有明确上限，不能因多个协程并发而重复填充；
- 下一页优先使用已测量缓存；
- 上一页优先使用边界栈或持久化稀疏锚点，不能永久保存全书页面；
- 翻页过程中取消旧请求，避免旧结果覆盖新页面；
- 到达末尾时返回明确 EOF 状态，不生成空白死循环页面。

### 9.2 数据安全规则

- 数据库只保存元数据、索引、位置和必要的短文本摘要，不保存完整正文；
- 书架移除不删除原始 TXT；
- 清理分页/章节缓存不删除进度、书签和书籍记录；
- SQLite 迁移失败时保留原数据库备份并进入可恢复错误状态；
- 写入进度采用幂等 upsert，应用进入后台和阅读页退出时各尝试保存一次；
- Android 进程被系统直接杀死不能保证最后一页，但必须保证最近一次成功保存的位置可恢复；
- 文件权限和 URI 不放在日志中完整打印，日志只记录脱敏标识。

### 9.3 缓存层次

```text
L1：当前页及相邻页正文/测量结果（内存）
L2：有限窗口 LRU（内存，有容量上限）
L3：章节/稀疏内容索引（SQLite）
L4：分页边界缓存（SQLite，可按排版签名清理）
L5：Android 非随机数据源私有副本（可清理，可重建）
```

V1 不缓存整本 TXT 的解码字符串。

## 10. 页面与交互方案

### 10.1 书架页

桌面和 Android 语义保持一致，视觉布局可平台化：

- 顶部：搜索、添加 TXT、设置；
- 中部：最近阅读；
- 主列表：书名、进度、最近打开时间、状态；
- 长按/右键：重命名、重新关联、删除书架记录、重建索引；
- 空状态：显示“添加 TXT 文件”主操作；
- 导入失败：显示具体原因，不生成半成品书籍记录。

V1 为控制复杂度，书架先使用根目录列表，不实现原方案中的多级分类树；分类接口和表可在 V1.1 加入。这样不会影响 TXT 阅读核心和未来 ZIP 扩展。

### 10.2 阅读页

#### 桌面

- 标题栏：书名、章节、进度状态；
- 中部：正文阅读区；
- 底部或临时菜单：上一页、下一页、目录、页码、书签、设置；
- 鼠标滚轮不滚动正文，默认映射为上一页/下一页或由设置决定；
- 左右方向键翻页，`Esc` 返回书架或关闭临时菜单；
- 窗口大小和 DPI 变化触发合并重排。

#### Android

- 处理 edge-to-edge 和状态栏内边距；
- 正文区使用固定页高，不加 `verticalScroll`；
- 左 1/3 点击上一页，右 1/3 点击下一页，中部显示/隐藏菜单；
- 临时菜单提供目录、页码跳转、书签和设置；
- 系统返回：菜单打开时先关闭菜单，否则从阅读页返回书架；
- 页面和按钮必须有 `testTag`、可访问语义和稳定的状态反馈。

### 10.3 设置页

V1 只提供全局设置。字号拖动时立即更新控件状态，重排请求在后台合并执行；设置页必须显示“正在重排/已完成/失败”状态，不能让用户误认为设置未生效。

### 10.4 错误状态

统一展示以下用户可理解的状态：

- 文件不存在；
- Android 文档权限失效；
- 文件无法随机访问，正在复制到私有缓存；
- 编码识别可信度低；
- 索引未完成；
- 需要重建索引；
- 文件格式不是 TXT；
- 文件读取失败；
- 正文为空。

底层错误码由 Rust 定义，UI 只做本地化文案映射，不根据异常字符串判断业务分支。

## 11. FFI 与并发契约

### 11.1 V1 最小接口

正式接口以稳定 C ABI 为跨语言基线，桌面直接使用同语义 Rust API：

```c
nr_engine_create(config)
nr_engine_destroy(handle)
nr_open_txt(handle, source_descriptor)
nr_close_book(handle, book_id)
nr_read_window(handle, chapter_index, offset, length)
nr_submit_page_boundary(handle, boundary)
nr_get_page_boundary(handle, layout_id, chapter_index, start)
nr_save_position(handle, position)
nr_get_position(handle, book_id)
nr_get_chapters(handle, book_id, start, count)
nr_create_bookmark(handle, bookmark)
nr_delete_bookmark(handle, bookmark_id)
nr_invalidate_layout(handle, layout_id)
nr_rebuild_index(handle, book_id, request_id)
nr_cancel_request(handle, request_id)
nr_get_last_error(handle)
```

接口设计要求：

- 句柄为不透明整数，禁止跨边界传递 Rust 对象；
- 字符串为 UTF-8 指针 + 长度，不能只依赖 NUL 结尾；
- 所有返回缓冲区明确由哪一方释放；
- ID 和字节偏移使用 64 位；JSON/字符串传输时保持精确，不让 JavaScript/JSON 数字截断；
- 单次正文返回受窗口上限约束；
- 错误使用稳定错误码 + 可读详情；
- 回调只传事件数据，不把 Activity、Compose 状态或 Rust 引用跨边界保存。

### 11.2 V1 并发策略

第一版不追求复杂的全异步 FFI。建议：

- UI 线程只发起轻量状态操作；
- 文件读取、章节扫描、分页和数据库操作在 Rust worker 或 Kotlin `Dispatchers.IO` 执行；
- 每个书籍阅读会话使用单一状态门闩，所有“打开书籍/切章/翻页/重排/保存位置”按顺序提交；
- 新的重排请求将旧请求标记取消，并只执行最终配置；
- 任务结果带 `request_id` 和 `layout_id`，过期结果不得覆盖当前状态；
- Activity 销毁时取消 UI 订阅，但不能无条件销毁仍被应用级任务使用的核心句柄；
- ViewModel 清理时先取消任务，再释放句柄。

## 14. 初始性能门槛

以下是 V1 的**初始工程门槛**，用于指导实现和测试；阶段 0 完成设备基线后允许通过 ADR 调整，但不能无证据降低标准。

### 14.1 内存与读取

- 不允许把 100MB 或 1GB TXT 全文载入内存；
- 单次数据源窗口不超过 256 KiB；
- 阅读状态内存应主要由当前页、预读页和有限 LRU 决定；
- 100MB 与 1GB 文件在相同页面停留时，稳定内存不应随文件大小线性增长；
- 章节扫描必须增量持久化，异常退出后可继续。

### 14.2 交互

- 已缓存的前后翻页目标：P95 内容更新延迟不超过 100ms；
- 未缓存但在有限窗口内可完成的翻页：P95 不超过 500ms；
- 首屏优先于完整章节/分页索引；
- 重排期间 UI 保持可操作，并显示状态，不允许长时间阻塞 UI 线程。

### 14.3 启动与空闲

- 首屏可交互时间在基准设备上记录中位数和 P95；
- 静止阅读 5 分钟不应存在固定周期的无意义重绘；
- Android 纯色静止阅读和桌面静止阅读均应记录 CPU、线程唤醒和内存；
- 功耗结论只使用物理 Android 设备，模拟器不得用于功耗结论。

### 14.4 包体

- Android 首发按 arm64 单 ABI 统计；
- Release APK/安装后占用、桌面完整发布目录和依赖必须一起统计；
- APK 中 JNI `.so` 必须经过符号剥离；
- 重新打包前删除旧 APK，避免增量构建残留尾部数据；
- 探针当前约 18MB Release APK 只能作为参考，不是正式 V1 承诺值。

## 15. 发布与运维方案

### 15.1 发布物

- Android：arm64-v8a Release APK；后续再评估 AAB；
- Windows：完整便携压缩包，包含所需运行库；
- Linux：明确支持的发行格式和系统依赖，至少提供可复现打包方式；
- 每个发布物附 SHA-256、版本号、构建提交标识和许可证清单。

### 15.2 签名与构建

- Debug 仅供开发安装；
- Release 必须使用正式签名配置，签名密钥不进入版本库；
- CI/发布机保存符号文件，用户包剥离调试符号；
- 构建脚本显式设置 SDK、NDK、Gradle、Rust 和 Slint 版本；
- 发布前运行 `aapt2 dump badging`、APK 内容检查、`apksigner verify` 和安装启动冒烟；
- 桌面发布目录必须在干净环境验证，不能只在开发机运行。

### 15.3 隐私与网络

V1 默认不请求网络权限，不含广告、遥测和账号服务。日志只保存本地必要诊断信息，不上传书名、路径、URI、正文或阅读位置。

### 15.4 升级与数据兼容

- SQLite 每次结构变化增加迁移版本，不直接覆盖用户数据库；
- 升级前自动备份数据库；
- 旧版索引版本不兼容时只删除可重建索引，不删除书籍、进度和书签；
- 若排版算法版本变化，旧分页缓存全部失效，内容位置仍尝试恢复；
- V1 不承诺跨设备数据同步。

## 16. 主要风险与控制措施

| 风险 | 影响 | 控制措施 |
|---|---|---|
| 双 UI 行为分叉 | 同一 TXT 在桌面和 Android 表现不一致 | Rust 共享位置/索引/存储语义；共同契约测试；平台只负责排版与交互 |
| SAF Provider 不支持随机访问 | 大文件无法按页跳转 | 检测能力；不支持时复制到私有缓存；复制可取消、可清理 |
| 测量与渲染口径不一致 | 半字、滚动条、页末裁切 | 像素统一、显式字距、回传实际行高、整行安全余量 |
| 大文件章节扫描耗电 | Android 卡顿和耗电 | 后台低优先级、可取消、增量持久化、前台操作让路 |
| 文件外部变化 | 旧索引指向错误内容 | 指纹检测后标记需重建，不自动覆盖；锚点恢复需校验附近文本 |
| JNI 生命周期错误 | 崩溃、泄漏、旧结果覆盖新页面 | 不透明句柄、request/layout 版本、串行状态门闩、销毁前取消 |
| Android edge-to-edge | 控件被状态栏遮挡 | 顶栏显式 `statusBarsPadding()`，真机回归固定检查 |
| Compose 默认字距/行高 | 分页结果与可见文本不一致 | 所有关键排版属性显式覆盖，并固定测试用例 |
| 探针代码直接演变为产品 | 模拟逻辑、占位接口混入正式版 | 分离正式目录；迁移一项验收一项；禁止保留空正文数据源 |
| 发布包残留旧内容 | 安装包体积和内容不可信 | 打包前清理旧产物，并进行 ZIP/APK 内容校验 |
| Linux/Windows 发布差异 | 开发机可运行，用户机不可运行 | 干净环境验证完整发布目录，明确系统依赖和最低版本 |

## 17. V1 完成定义

只有以下条件全部满足，才允许称为“V1 完成”：

### 产品功能

- [ ] TXT 导入、书架显示、删除记录、重新关联完整可用；
- [ ] UTF-8、UTF-16、GB18030/GBK、Big5 代表文件可正确阅读；
- [ ] 有限窗口读取和大文件首屏可用；
- [ ] 章节索引、章节跳转、整页翻页可用；
- [ ] 字号/排版设置会正确重排；
- [ ] 进度和书签可保存恢复；
- [ ] 文件失效和缓存清理不会造成误删；
- [ ] V1 未实现项没有以半成品入口对用户开放。

### 技术质量

- [ ] Rust 核心单元、属性、契约测试通过；
- [ ] 桌面 Linux/Windows 发布物可在干净环境运行；
- [ ] Android 12+ 安装、启动、SAF、返回、旋转、后台恢复和进程重建通过；
- [ ] JNI 错误、取消、释放和重复打开测试通过；
- [ ] 200 页正向/100 页反向分页无丢字、重字、非法边界；
- [ ] 100MB 和 1GB 压力测试证明没有全文载入；
- [ ] 静止阅读无持续无意义刷新；
- [ ] Release 包体、签名、依赖和许可证完成核验；
- [ ] 已知问题、数据迁移和回滚说明齐全。

### 证据要求

每个门禁必须保留：

- 执行命令；
- 工具链和设备版本；
- 原始日志；
- 结构化结果；
- 失败时的复现步骤和修复记录；
- 人工真机验收的日期、机型、系统版本和未覆盖项。

“代码存在”“构建成功”或“探针自报通过”都不能单独作为 V1 完成证据。

## 18. 后续版本边界

V1 发布后再按以下顺序扩展：

1. V1.1：ZIP 多 TXT 组成整书、自然排序、流式解压缓存；
2. V1.2：多级分类、每本书独立设置、正文搜索；
3. V1.3：背景图片、更多字体和阅读主题；
4. 后续：EPUB 等格式、连续滚动、同步或其他联网能力。

每次扩展必须复用 V1 的 `TextSource`、`ContentPosition`、索引版本、布局签名和缓存安全规则，不允许为 ZIP 或 EPUB 另造一套进度/书签/分页位置体系。

---

## 19. 当前下一步

正式进入开发时按以下顺序执行：

1. 确认本方案作为 V1 基线，并冻结 V1 排除项；
2. 创建正式 Rust workspace、Android 工程和桌面工程；
3. 迁移并清理共享核心，先让正式 crate 的核心测试通过；
4. 完成真实桌面 TXT 数据源和 Android SAF 有限窗口数据源；
5. 完成 SQLite 初始迁移；
6. 实现 V1.0-alpha 的单 TXT 阅读闭环；
7. 在 Linux 和 Android 真实设备上验收后，再扩展书架、书签和完整索引；
8. Windows 发布与 Android 生命周期自动化测试完成前，不宣称 V1 可发布。

本方案的核心取舍是：**先把 TXT 的真实读取、中文分页、位置恢复和本地数据安全做成稳定产品，再扩展 ZIP 和其他格式；允许两套 UI 存在，但不允许两套阅读业务存在。**
