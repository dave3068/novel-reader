# 以网络存储作为跨设备同步介质的可行性调研

> 调研日期：2026-10-25
> 范围：同一用户，在 Linux/Windows 桌面与 Android 之间同步阅读进度、书签/分类/设置，以及新导入的 TXT 书籍文件。
> 性质：**可行性调研**。阶段 0（目录包）与阶段 1（WebDAV）的实现记录见
> `docs/research/sync-phase0-implementation.md`、`docs/research/webdav-sync-implementation.md`。本文中的配额、价格、接口限制均来自公开资料或社区实测，平台政策可能随时变化；落地前必须按本文 §9 的验证计划重新实测。
> 关联基线：`docs/novel-reader-solution.md` §3.2 目前把「跨设备同步」列为范围外；如要实施，需先更新范围/验收文档，而不是仅加一个后台任务。

## 0. 结论摘要

1. **技术上可行，但不应直接同步 `library.db`。** SQLite 文件带 WAL、行锁、设备本地 `rowid` 和布局缓存，直接放进网盘会产生损坏、主键冲突和互相覆盖。正确做法是同步**逻辑记录**（进度、书签、分类、设置）和**按内容哈希寻址的书籍副本**，本地数据库只作为各设备的物化视图。
2. **元数据同步几乎零成本。** 1,000 本书的进度/书签/分类/设置序列化后约 1 MB 量级，压缩后几百 KB；任何 5–20 GB 免费额度都远远够用。真正的成本在**书籍文件体积、首次同步流量和网盘限速**。
3. **百度网盘不是首选的第一后端，但对「单人自用」是可行的。** 百度开放平台提供「个人使用」应用：免上线审核、直接上线、最多 10 个用户；文件接口被限制在 `/apps/{应用名}` 沙箱内；OAuth 授权码模式可用，refresh token 有效期约 10 年。问题在于：未审核应用的官方配额是 **10 次请求/小时**、非会员下载速度约 100 KB/s 量级、公开分发需要上线审核、桌面/开源客户端无法真正保守 `client_secret`。这些限制使其适合个人试水，不适合作为面向公众的唯一同步方案。
4. **最合适的通用方案是 WebDAV-first。** 一套 WebDAV 客户端可同时覆盖坚果云、InfiniCLOUD、Nextcloud、群晖/威联通 NAS、以及用户自建的 OpenList 网关；国内可用、免费额度够、无需应用审核、用户只需填 URL + 应用密码。代价是坚果云免费版有 600 请求/30 分钟、500 MB/文件、750 条目/请求等限制，需要做批量与退避。
5. **「本地文件夹 + 网盘客户端」是兼容百度网盘的最低成本路线。** 应用只读写用户指定的一个普通文件夹，由百度网盘同步空间/坚果云客户端/OneDrive 客户端负责搬运。桌面端今天就能用；Android 端受百度同步空间不支持任意文件夹、后台同步不可靠的限制，只能作为过渡或手动方案。
6. **对象存储（S3 兼容）是「一年几元钱、稳定、无需审核」的进阶路线。** 七牛云 Kodo 每月 10 GB 标准存储 + 10 GB CDN 流量免费、S3 兼容、国内节点；Cloudflare R2 10 GB 免费且出网免费；Backblaze B2 10 GB 免费；阿里云 OSS/腾讯云 COS 按量约 0.12 元/GB/月。适合愿意填 Bucket/AK/SK 的用户，或书库超过 3 GB 的用户。
7. **不建议作为产品依赖的途径：** 115（API 已于 2026-08 暂停）、阿里云盘个人开发者（社区反馈 2025-12 起仅企业可开通，需以控制台为准）、123 云盘 WebDAV（需 VIP 且稳定性有争议）、Syncthing Android（官方应用 2024-12 停止，社区 fork 也已归档）、Google Drive/Dropbox（中国大陆不可用）、iCloud（无 Linux 且需 99 美元/年开发者账号）。
8. **建议分阶段落地：**
   - **阶段 0（低风险，先验证合并语义）**：导出/导入一个 `.nrsync` 同步包（`state.json` + `books/<sha256>.txt`），用户可放进任何被网盘客户端同步的文件夹，或手动经微信/网盘传递。
   - **阶段 1（推荐主路线）**：WebDAV 后端，自动增量同步；优先坚果云（国内）与 InfiniCLOUD（20 GB）。
   - **阶段 2（进阶）**：S3 兼容后端（七牛/R2/B2/OSS/COS/MinIO），解决大书库与请求配额问题。
   - **阶段 2/3（后续）**：S3、百度网盘官方 API 适配器，仅面向「愿意自己创建百度个人使用应用」的用户；公开分发前先解决审核与凭证问题。

## 1. 需求拆解：哪些数据需要同步

| 数据 | 典型体积 | 变更频率 | 能否重建 | 同步策略 |
|---|---:|---|---|---|
| 阅读进度（`reading_progress`） | 约 100 B/本 | 每次阅读/退出 | 否 | 按书 + 设备记录，合并冲突 |
| 书签（`bookmarks`） | 约 100–300 B/条 | 低 | 否 | 按稳定 UUID 并集合并，删除用墓碑 |
| 分类树（`book_categories` + `books.category_id`） | 几十 B/节点 | 低 | 否 | 按稳定 UUID 合并，合并后做环检测 |
| 全局阅读设置（`reader_settings`） | < 1 KB | 低 | 否 | 白名单字段同步，设备相关项可选 |
| 阅读历史（`reading_history`） | 约 100 B/条 | 高 | 可丢弃 | 默认仅本地；如同步按事件 UUID 追加 |
| 书籍元数据（书名、编码、来源） | 约 0.5–2 KB/本 | 低 | 部分可重建 | 按内容哈希/稳定 UUID 同步 |
| **书籍文件（TXT）** | 0.1–20 MB/本 | 仅导入时 | 否（用户原始文件只读） | 内容哈希寻址，按需上传/下载 |
| 章节索引（`chapters`） | 与书大小相关 | 导入/重建时 | 是 | **不同步**，各设备本地重建 |
| 分页缓存（`layout_records`） | 与书大小/布局相关 | 布局变化时 | 是 | **不同步**，布局签名因设备而异 |
| 背景图（V1.1） | 几百 KB–几 MB | 低 | 否 | 可选同步，按内容哈希 |

关键结论：

- **元数据与书籍文件必须分开设计。** 进度状态可以每分钟同步；书籍文件只在新增时上传一次，不能每次同步都扫全库。
- **书籍身份不能用路径或 `source_locator`。** Android 的 SAF URI、桌面路径、私有副本路径都是设备本地的；跨设备必须用内容哈希（建议 SHA-256）或稳定 UUID。
- **`source_fingerprint` 不能当同步身份。** 现有实现是头/中/尾采样的 FNV 指纹（见 `crates/reading-source/src/fingerprint.rs`），用于「同一文件重新关联」足够，但不是抗碰撞的全文件哈希；同步新书时需要补一个全文件 SHA-256。
- **数据库中的 `id` 是设备本地 `INTEGER PRIMARY KEY`。** 不能把一端的 `books.id` 直接搬到另一端；同步层必须做「远端稳定 ID ↔ 本地 id」映射。
- **原始 TXT 永远只读。** 同步、下载、去重、清理都只能操作应用自己的副本或缓存，不能修改/删除用户原文件（与 AGENTS.md 的硬约束一致）。

## 3. 百度网盘：能做到，但限制比想象中多

### 3.1 官方开放平台的可用能力

截至 2026-10-25，百度网盘开放平台的公开文档明确支持「应用数据存储」场景：第三方应用可以在用户授权后，把应用产生的数据上传到用户自己的网盘。具体约束如下。

| 项目 | 现状 | 对同步的影响 |
|---|---|---|
| 开发者认证 | 个人实名认证后可创建 **1 个应用**；企业认证最多 10 个 | 个人开发者只能维护一个 AppId，换应用要删除重建 |
| 应用用途 | **个人使用**：免上线审核、创建后直接上线、**限 10 个用户**；**公开发布**：需提交上线审核，通过后不限人数 | 单人/家庭自用足够；公开分发必须审核 |
| 应用目录 | 第三方应用只能访问 `/apps/{应用名}`（用户看到的是「我的应用数据/{应用名}」）；2026-06-03 后创建的应用，文件下载/列表/管理/预上传/元信息/移动等接口仅支持该目录 | 只能同步自己的数据，不能当通用网盘客户端；这反而降低隐私风险 |
| 未审核配额 | 官方《权限与配额》写明：未通过/未提交上线审核的应用，接口频率 **10 次/小时**、最大用户数 10；超限返回 20012/20011 | 若「个人使用」也沿用此配额，自动同步基本不可用；**必须先在控制台/工单确认个人使用模式的实际频率** |
| OAuth | 授权码模式（需要 `client_secret`）或简化模式（无 refresh token）；无 server 应用官方支持 `redirect_uri=oob` | 桌面端可走系统浏览器 + oob（本地回调需确认）；开源客户端无法真正保守 secret |
| Token | access token 短期有效，refresh token 约 10 年 | 长期免登录可行，但 refresh token 泄露风险高，必须放系统密钥库 |
| 下载 | 先 `filemetas` 拿 `dlink`（8 小时有效），再带 `User-Agent: pan.baidu.com` 下载；可能 302；>50 MB 不允许浏览器直接下，需原生客户端 | 应用是原生客户端，技术上可行；实现要处理 302、Range、链接过期 |
| 上传 | 预上传 + 分片/秒传；小文件可直接上传 | TXT 体积小，上传不是瓶颈；秒传需要计算百度要求的哈希 |
| 限速 | 非会员账号下载速度常被社区实测为约 100 KB/s 量级，随会员/时段变化 | 1 GB 书库首次同步可能需要数小时；进度元数据不受影响 |

> 重要：官方文档没有把「个人使用」模式的频率配额单独写清楚。上表的 10 次/小时是「未通过上线审核」口径；个人使用应用虽然免审核，但**不能假设它自动获得生产配额**。这是百度方案能否成立的第一验证项。

### 3.2 单人自用的可行性判断

**可行，但只建议作为可选适配器，不建议作为第一版或唯一后端。**

成立条件：

- 用户愿意注册百度开放平台、完成实名认证、创建一个「个人使用」应用；
- 该应用的实际接口频率足够（至少每分钟几次，而不是 10 次/小时）；
- 用户接受非会员限速，或已有会员；
- 应用只同步自己的 `/apps/{应用名}` 目录，不尝试遍历用户网盘；
- 桌面端用系统浏览器完成 OAuth，token 存 OS 密钥库；不在日志中打印 token。

不成立/不推荐的情况：

- **面向公众分发。** 需要上线审核；审核材料、周期、资质要求不受本项目控制；审核不通过就没有配额。
- **把开发者 AppKey/Secret 硬编码进 GPL 开源客户端。** 任何人都能提取并滥用你的应用配额；10 用户上限虽能限制影响，但公开版本的用户无法共用同一个应用。
- **把百度当作唯一云。** 115 的 API 在 2026-08-09 直接暂停，说明平台 API 可能一夜之间不可用；必须有导出/迁移路径。
- **同步大书库。** 非会员限速 + 可能的请求配额，使首次同步体验很差。

### 3.3 百度「同步空间」不是跨平台 API 替代品

百度网盘客户端自带「同步空间」，免费版公开资料称每月约 1 GB 同步流量、单文件最大 4 GB，支持多设备自动同步和历史版本。但它面向的是**桌面客户端同步本地文件夹**：

- 桌面端可以把应用的数据目录放进同步空间，实现「本地文件夹桥」；
- Android 端不能把任意应用私有目录挂进百度同步空间，也无法保证后台实时同步；
- 因此它不能替代 WebDAV/API 实现 Android ↔ 桌面自动同步，只能作为桌面端的过渡方案。

### 3.4 百度方案的风险清单

| 风险 | 说明 | 缓解 |
|---|---|---|
| 配额 | 未审核 10 次/小时；个人使用模式待确认 | 先做 24 小时配额实测；批量操作用单包上传；失败退避 |
| 审核 | 公开发布需上线审核 | 首发只做「自带应用凭证/个人使用」模式；公开版不承诺百度 |
| 限速 | 非会员约 100 KB/s 量级 | 只同步元数据；书籍按需下载；提示用户会员/换后端 |
| 凭证 | 桌面/开源客户端无法保守 `client_secret`；refresh token 10 年 | 每用户自建应用；token 放系统密钥库；支持撤销/退出登录 |
| 平台变更 | API 可能调整/暂停（115 前例） | 同步层 provider-agnostic；保留导出包；不把云当唯一副本 |
| 隐私 | 网盘可能做内容审核/扫描；书籍可能涉版权 | 明确告知并默认只同步元数据；可选端到端加密；不主动上传用户未选择的书 |
| 路径 | 只能 `/apps/{应用名}`；应用名 0–12 字 | 用 ASCII 哈希做文件名；显示名放 JSON；应用名提前规划 |

## 4. 其他个人可用途径

### 4.1 国内 WebDAV：综合最优的免费/低价路线

| 服务 | 免费额度 | 协议/接口 | 价格 | 优点 | 限制 |
|---|---|---|---:|---|---|
| **坚果云** | 每月上传 1 GB、下载 3 GB；空间随使用增长 | 官方 WebDAV（`https://dav.jianguoyun.com/dav/`）+ 客户端 | 免费；专业版约 ¥199/年 | 国内速度稳定、官方 WebDAV、应用密码可撤销、Linux/Windows/Android 客户端齐全 | 600 请求/30 分钟（免费）、500 MB/文件、单次 750 条目；首次大批量同步会触发限流 |
| **InfiniCLOUD**（原 TeraCLOUD） | 20 GB（邀请活动可能额外赠送，以官网为准） | 官方 WebDAV | 免费；付费扩容 | 容量大、WebDAV 官方支持、日本节点 | 海外延迟；免费账号长期不登录（约 2 年）可能被删除；国内速度待实测 |
| **Nextcloud / 群晖 / 威联通 / TrueNAS** | 取决于自有硬件 | WebDAV/Nextcloud API | 软件免费；硬件/电费 | 完全可控、无第三方配额、可内网 | 需要一台常在线设备；外网访问需公网 IP/DDNS/Tailscale；运维成本 |
| **123 云盘** | 2 TB 免费空间；每月 10 GB 提取流量 | 官方 WebDAV（社区说明需 VIP）、OpenAPI（社区称约 ¥20/月） | VIP/按量 | 容量大、国内速度快 | WebDAV 不是免费能力；社区对稳定性有争议；OpenAPI 付费；不适合作为唯一后端 |
| **OpenList / AList 网关** | 取决于上游网盘 | 把百度/阿里/123 等挂成 WebDAV | 软件免费 | 能让不支持 WebDAV 的网盘「变成」WebDAV | 部分驱动依赖非官方接口，可能触发风控/封号；不建议作为产品依赖，只适合高级用户自担风险 |

**为什么 WebDAV 适合本项目：**

- 一套客户端覆盖多家服务，不需要为每家写 OAuth/审核；
- 用户用「应用密码」而不是账号密码，可随时撤销；
- Linux/Windows/Android 都能发 HTTPS 请求；
- 文件语义简单（PUT/GET/PROPFIND/MOVE），容易做原子写和增量同步；
- 免费额度对 TXT 书库足够；超出时换对象存储即可。

**必须处理的 WebDAV 限制：**

- 坚果云 600 请求/30 分钟：首次同步 1,000 本书不能「一本书一个请求」地猛传；应先传一个压缩包/分批，或只同步元数据，书籍按需下载；
- 500 MB/文件：TXT 不受影响；ZIP 整书包要分卷；
- 750 条目/请求：目录列举要分页；
- 部分服务对 `MOVE`、`MKCOL`、`PROPFIND Depth` 的实现有差异，需要兼容性测试；
- 服务端可能返回 503/429，需要指数退避和「稍后重试」，不能把失败当空数据覆盖本地。

### 4.2 国内对象存储：一年几元钱的稳定路线

| 服务 | 免费额度 | 价格（超出后，公开价） | 协议 | 备注 |
|---|---|---|---:|---|---|
| **七牛云 Kodo** | 标准存储 10 GB/月、CDN 回源 10 GB/月、PUT 10 万次/月、GET 100 万次/月 | 约 0.1 元/GB/月量级 | S3 兼容 + 原生 API | 国内节点、需实名；免费额度按月刷新；适合书库 + 元数据 |
| **阿里云 OSS** | 国内站按量；国际站有 0–5 GB 免费口径 | 标准存储约 **0.12 元/GB/月** | S3 兼容（部分）+ 原生 API | 稳定、生态全；需实名；流量/请求另计；1 GB 书库一年约 1.5 元 |
| **腾讯云 COS** | 新用户个人 50 GB 标准存储，有效期 6 个月 | 标准存储约 0.118 元/GB/月 | S3 兼容 + 原生 API | 免费额度大但有期限；需实名；适合试水 |
| **Cloudflare R2** | 10 GB-month、100 万 Class A、1,000 万 Class B/月；出网免费 | $0.015/GB/月 | S3 | 海外；开通可能要求绑定支付方式（以控制台为准）；国内延迟待实测 |
| **Backblaze B2** | 10 GB 存储；每月出网为平均存储的 3 倍以内免费 | $6.95/TB/月（约 $0.00695/GB/月） | S3 | 海外；注册不强制信用卡；国内速度一般 |
| **MinIO / 自建** | 自有硬件 | 0 | S3 | 完全可控；需要运维和外网入口 |

**对象存储的优点：**

- 没有「网盘客户端」式的限速和请求频率（免费额度内请求数很多）；
- S3 协议稳定、工具链成熟，适合增量同步和内容哈希寻址；
- 书籍文件与元数据可以放同一个 Bucket，用前缀隔离；
- 不需要应用审核，也不需要把开发者 secret 发给用户。

**缺点：**

- 用户要自己建 Bucket、配 AK/SK，门槛高于 WebDAV；
- AK/SK 是长期凭证，泄露后果比 WebDAV 应用密码更严重；应使用最小权限的子账号/密钥；
- 国内 OSS/COS/七牛需要实名，部分还涉及备案/域名（私有 Bucket + SDK 不需要自定义域名）；
- 海外 R2/B2 在中国大陆的延迟和稳定性不稳定，必须实测。

## 6. 推荐方案

### 6.0 决策矩阵

评分口径：成本（越高越省）、接入难度（越高越容易）、国内可用、跨平台、可控性（数据/凭证自主），1–5 分；推荐度是综合判断，不是严格加权。

| 方案 | 成本 | 接入难度 | 国内可用 | 跨平台 | 可控性 | 推荐度 | 适用场景 |
|---|---:|---:|---:|---:|---:|---|---|
| WebDAV + 坚果云免费 | 5 | 5 | 5 | 5 | 4 | **首选** | 个人、国内、书库 ≤ 3 GB |
| WebDAV + InfiniCLOUD | 5 | 5 | 3 | 5 | 4 | 推荐 | 书库 20 GB 内、能接受海外延迟 |
| WebDAV + Nextcloud/NAS | 5（自有硬件） | 3 | 5 | 5 | 5 | 推荐 | 已有 NAS/常开服务器 |
| 本地文件夹 + 百度同步空间 | 5 | 5 | 5 | 2（Android 弱） | 4 | 过渡/备份 | 桌面为主、不想注册 API |
| S3 + 七牛/R2/B2/OSS | 5 | 3 | 4（七牛/OSS 好） | 5 | 5 | 进阶 | 大书库、技术用户、多设备 |
| 百度官方 API（个人使用） | 5 | 3 | 5 | 4 | 3 | 可选 | 单人自用、愿意实测配额 |
| 百度官方 API（公开发布） | 4 | 2 | 5 | 4 | 3 | 不优先 | 需要面向公众且能过审核 |
| 123 云盘 WebDAV/OpenAPI | 4 | 3 | 5 | 5 | 3 | 备选 | 已有 123 VIP，能接受不稳定 |
| Syncthing（自带客户端） | 5 | 2 | 4 | 3 | 5 | 不推荐内置 | 用户自己已用 Syncthing |
| Google Drive/Dropbox/OneDrive | 5 | 3 | 1–2 | 5 | 3 | 不适用 | 海外用户 |
| 直接同步 SQLite | 5 | 5 | — | 5 | 1 | **禁止** | — |

### 6.1 首选：WebDAV 后端（坚果云 / InfiniCLOUD / Nextcloud / NAS）

**推荐理由：**

- 一套实现覆盖多个服务，不被单一平台绑定；
- 用户自带账号，应用不需要申请开发者应用、不需要上线审核；
- 免费额度足够 TXT 场景；
- 语义简单，便于实现原子写、断点重试、增量同步；
- 未来可把 OpenList 作为高级用户的桥，把百度/阿里等挂成 WebDAV（但产品不承诺）。

**默认配置建议：**

- 同步根目录：用户指定，例如 `/novel-reader/`；
- 状态文件：`devices/<device_id>/state.json.gz`（每设备只写自己的文件）；
- 书籍文件：`books/<sha256>.txt`（不可变，按内容去重）；
- 元数据只同步进度/书签/分类/设置白名单；章节/分页缓存不同步；
- 书籍文件同步默认**开启但可关**，并设单本/总量上限（例如单本 50 MB、总量 2 GB），超限提示改用对象存储；
- 首次同步用「单包 + 分批」避免坚果云 600 请求/30 分钟限制；后续增量。

**用户配置成本：**

- 坚果云：注册 → 账户信息 → 安全选项 → 添加应用密码 → 在应用里填 `https://dav.jianguoyun.com/dav/`、邮箱、应用密码；
- InfiniCLOUD：注册 → 开启 WebDAV → 填 URL/账号/密码；
- Nextcloud/NAS：填自己的 WebDAV URL + 账号 + 应用密码（建议单独建同步账号）。

### 6.2 兼容百度网盘：本地文件夹桥（阶段 0/过渡）

**做法：**

- 应用提供一个「同步文件夹」设置；
- 用户把该文件夹放进百度网盘「同步空间」、坚果云同步目录、OneDrive 目录，或任何被客户端同步的目录；
- 应用在启动/退出/手动点击时写入并合并 `.nrsync` 包；
- 桌面端可做到接近自动；Android 端只能手动选择 SAF 目录或定时检查，不能依赖百度客户端后台。

**优点：**

- 不需要百度 API、不需要审核、不需要开发者凭证；
- 今天就能用百度网盘（桌面）；
- 同时天然获得网盘的历史版本/回收站；
- 实现成本最低，可先验证合并逻辑。

**缺点：**

- 依赖外部客户端运行和登录；
- 冲突由网盘客户端产生「冲突副本」，应用需要识别/合并；
- Android 跨平台体验差；
- 无法知道云端是否同步完成，状态提示容易误导。

**定位：** 不是最终方案，而是**阶段 0 的验证载体 + 永久可用的手动备份/迁移通道**。

同理，阿里云盘、夸克、115 等如果其桌面客户端提供「本地文件夹同步/备份」能力，也可以用这个桥；但它们目前没有可用的个人官方 API（阿里云盘个人开发者关闭、115 API 暂停），所以只能作为桌面端过渡，不能作为自动跨平台方案。

### 6.3 进阶：S3 兼容对象存储（大书库/技术用户）

- 适用：书库 > 3 GB、需要大量设备首次同步、或用户已有对象存储；
- 推荐国内：七牛云 Kodo（10 GB 免费、S3 兼容）、阿里云 OSS、腾讯云 COS；
- 推荐海外：Cloudflare R2（10 GB 免费、出网免费）、Backblaze B2（10 GB 免费）；
- 配置：Endpoint、Region、Bucket、Access Key、Secret Key；建议用户建子账号，只授权该 Bucket 的 Get/Put/List/Delete；
- 安全：AK/SK 存系统密钥库；不在日志/崩溃报告里出现；支持「清除凭证」。

### 6.4 可选：百度网盘官方 API（最后做）

只在以下条件同时满足时做：

1. 有明确的「百度网盘用户」需求，而不是「想支持所有网盘」；
2. 实测「个人使用」应用的接口频率足够（至少每分钟几次）；
3. 能接受只服务 10 个用户，或愿意走公开上线审核；
4. 有明确的凭证方案（每用户自建应用 / 受控代理 / 仅自用构建）。

实现上建议：

- 只访问 `/apps/{应用名}/novel-reader/`；
- 状态文件与书籍文件沿用 WebDAV 的布局，适配器只替换传输层；
- 上传用预上传/分片；下载处理 302、`User-Agent: pan.baidu.com`、dlink 8 小时过期、Range；
- OAuth 用系统浏览器 + oob（或确认可用的本地回调）；refresh token 存 OS 密钥库；
- 首次授权后做一次「配额探测」：连续发少量请求，记录 20012/20011，给出可读提示；
- 不做「扫描用户网盘」「自动转存分享链接」等超出同步范围的事。

### 6.5 不建议的路线

| 路线 | 原因 |
|---|---|
| 直接同步 `library.db` / `-wal` / `-shm` | 损坏、锁、主键冲突、布局缓存污染；跨设备不可合并 |
| 只同步 `library.db` 的不同副本，按修改时间覆盖 | 会丢另一台设备的进度/书签；SQLite 不是 CRDT |
| 依赖 115 API | 2026-08-09 起暂停服务，恢复时间未知 |
| 依赖阿里云盘个人开发者 API | 社区反馈 2025-12 起仅企业可开通；需以控制台为准；不适合作为唯一方案 |
| 123 云盘 WebDAV 作为唯一后端 | 需 VIP、稳定性有争议、免费流量有限 |
| Syncthing Android 作为内置同步 | 官方应用已停止，fork 归档；后台/权限问题长期存在 |
| Google Drive / Dropbox | 中国大陆不可直接用 |
| 把 client_secret 硬编码进公开客户端 | 凭证必然泄露；配额/风控不可控 |

## 7. 技术设计要点（针对本仓库）

### 7.1 不要同步数据库文件

`reading-storage` 使用 SQLite（WAL、外键、`INTEGER PRIMARY KEY`、迁移器）。跨设备直接复制数据库会带来：

- 两台设备同时写 → 文件级覆盖，丢失更新；
- `books.id`、`book_categories.id`、`bookmarks.id` 是本地自增，合并即冲突；
- `layout_records` 绑定本机布局签名，同步过去是脏缓存；
- 迁移版本可能不同，旧库覆盖新库会触发降级/损坏；
- WAL/SHM 边车文件不属于可移植数据。

正确做法：**导出逻辑记录 → 合并 → 写回本地库**。数据库仍然是每台设备的本地真相，云端只是交换介质。

### 7.2 身份模型

建议新增（迁移 `0003_*.sql`，只增不删）：

| 概念 | 建议 | 说明 |
|---|---|---|
| 设备 ID | 随机 UUID，首次启动生成，存 `app_meta` 或独立表 | 每设备状态文件名、冲突裁决用 |
| 书籍稳定 ID | 内容 SHA-256（首选）或随机 UUID（无法算哈希时） | 同内容不同路径 → 同一本；不同内容同书名 → 两本 |
| 分类/书签稳定 ID | 随机 UUID | 现有自增 id 只在本机有效 |
| 逻辑时钟 | 每设备单调递增 `seq`；合并时取 `max(seen)+1` | 不依赖系统墙钟，避免时钟漂移 |
| 墓碑 | `(entity_type, sync_id, deleted_seq, device_id)` | 删除也要同步，否则会「复活」 |
| 内容哈希 | 全文件 SHA-256，流式计算 | 现有采样 FNV 指纹继续用于重新关联，不替代 SHA-256 |

映射表可以独立于业务表，避免改动既有语义：

```sql
-- 示意，不是最终迁移
CREATE TABLE sync_identity (
    entity_type TEXT NOT NULL,      -- book / category / bookmark
    local_id    INTEGER NOT NULL,
    sync_id     TEXT NOT NULL,      -- uuid 或 sha256
    content_hash TEXT,              -- 仅 book
    updated_seq INTEGER NOT NULL,
    device_id   TEXT NOT NULL,
    deleted_at  INTEGER,
    PRIMARY KEY (entity_type, local_id),
    UNIQUE (entity_type, sync_id, device_id)
);
```

也可以直接在 `books`/`book_categories`/`bookmarks` 加 `sync_id`、`content_hash` 列；两种都可，关键是**不要复用本地自增 id 作为跨设备身份**。

### 7.3 云端目录布局（provider-agnostic）

```text
<sync-root>/
  devices/
    <device-a-uuid>/
      state.json.gz          # 该设备写、其他设备只读
    <device-b-uuid>/
      state.json.gz
  books/
    <sha256>.txt             # 不可变；按内容去重
```

- **每设备只写自己的 `state.json.gz`**：没有共享可变清单，天然避免最后写入覆盖；
- 合并时列出 `devices/*/state.json.gz`，下载比本地 `last_seen_seq` 新的文件，合并后写自己的新 `seq`；
- 书籍 blob 不可变：先 `HEAD`/`PROPFIND` 判断是否存在，不存在才上传；上传用临时名 + `MOVE`（WebDAV）或直接 `PUT`（S3 对象原子）；
- 首次同步可以把多本书打成一个包，减少请求数；后续按需单本；
- 状态文件 gzip；书籍是否压缩可选（TXT 压缩率通常 40–60%，但会增加 CPU 和兼容性）。

`state.json` 示意：

```json
}
```

> 注意：`last_page_hint`、页码、总页数**不要跨设备使用**；布局不同，页码必然不同。只同步内容位置（`content_unit_id` + `byte_offset` + `nearby_fingerprint`）和章节序号。

### 7.4 合并规则

| 数据 | 规则 | 冲突处理 |
|---|---|---|
| 阅读进度 | 每设备每本保留一条；按 `(updated_seq, device_id)` 取最新 | 若两台设备在上次同步后都改过，标记冲突，弹窗让用户选「本机/云端/查看位置」；不要静默丢进度 |
| 书签 | 按 `sync_id` 并集；删除用墓碑 | 同 ID 内容不同 → 取较新；标题冲突可保留两条 |
| 分类 | 按 `sync_id` 合并；父节点缺失时挂根；合并后做环检测（复用现有防护） | 同父同名：合并为一个分类（书籍取并集），或加设备后缀；需在 UI 说明 |
| 书籍 | 按 `content_hash` 去重；同内容不同书名 → 保留一个显示名，可提示用户 | 同名不同内容 → 两本都保留 |
| 设置 | 白名单：主题、字体、字号、行距、段距、默认编码；设备相关项（边距/背景）默认不覆盖 | 逐字段 `(seq, device)` 取新；提供「恢复本机布局」 |
| 历史 | 默认不同步 | 如需同步：事件 UUID 追加，不做删除 |
| 章节/分页 | **不同步** | 各设备按本地规则重建；`index_version` 不同则进度按字节偏移恢复 |

### 7.5 传输与原子性

| 传输 | 列表 | 读 | 写 | 原子性 | 备注 |
|---|---|---|---|---|---|
| WebDAV | `PROPFIND Depth:1` | `GET` | `PUT`/`MKCOL` | 临时名 + `MOVE` | 坚果云限制 600 请求/30 分钟；需退避 |
| S3 | `ListObjectsV2` | `GetObject` | `PutObject` | 对象级原子 | 大文件分片；AK/SK 最小权限 |
| 百度 | `list`/`filemetas` | `dlink` + GET | 预上传 + 分片 | 上传后 `filemanager` 移动 | 10 次/小时（未审核口径）需先验证 |
| 本地文件夹 | 目录遍历 | 读文件 | 临时文件 + rename | 同盘 rename 原子 | 依赖外部客户端，冲突副本需处理 |

通用要求：

- 所有网络操作可取消、可超时、可重试；重试用指数退避 + 抖动；
- 区分「网络失败」与「云端为空」：失败绝不能写空状态覆盖本地；
- 下载先写临时文件，校验长度/哈希后再替换；
- 书 blob 文件名用 `sha256`（ASCII），避免中文/空格/NFC 问题；
- 单次同步有总时长/总字节上限，避免 Android 后台被杀；
- 日志脱敏：URL 中的 token、Authorization、AK/SK、书籍路径都要打码。

### 7.6 安全与隐私

- **凭证存储：** Android 用 Keystore/EncryptedSharedPreferences；Linux 用 libsecret（若桌面环境支持）；Windows 用 Credential Manager。当前项目没有 keyring 依赖，新增时需评估可移植性和打包依赖；不能明文放 `library.db` 或日志。
- **最小权限：** WebDAV 用独立应用密码；S3 用只授权单 Bucket 的子账号；百度 token 只用于 `/apps` 目录。
- **传输：** 只允许 HTTPS；校验证书；不提供「忽略证书错误」的默认选项。
- **端到端加密（可选）：** 对书籍和状态做客户端加密可以避免网盘扫描，但会带来密钥恢复、换设备、忘记密码等问题。建议先不做默认加密，明确告知用户网盘可见；有需求再加「加密同步」开关（Argon2id 派生密钥 + 随机 nonce，书籍按 blob 加密）。
- **版权/合规：** 只同步用户自己导入的 TXT；默认只同步元数据，书籍同步需用户明确开启；不提供分享/转存/公开链接功能；遵守各网盘 ToS。
- **数据出境：** 使用 R2/B2/InfiniCLOUD 等海外服务时，书籍和进度会出境；个人自用一般可控，但产品化时要说明。

### 7.7 Android 与桌面差异

| 主题 | 桌面（Rust/Slint） | Android（Kotlin/Compose） |
|---|---|---|
| 触发时机 | 启动、退出、手动「立即同步」、可选定时 | WorkManager（网络约束、电量约束）、前台手动；系统可能延迟/杀掉 |
| 文件来源 | 原始路径或应用副本 | SAF URI、应用私有副本；跨设备必须下载副本或用 SAF 目录 |
| 凭证 | 系统密钥环；Linux 可能需 libsecret | Keystore/EncryptedSharedPreferences |
| 后台限制 | 无 | Doze/后台限制；不能保证「实时」 |
| 首次同步 | 可长时间跑，显示进度 | 建议前台 + 通知；大库分几次 |
| 冲突提示 | 对话框 | 通知/对话框；不要静默覆盖 |

**Android 特别注意：**

- SAF URI 的持久权限可能失效；同步下载的书应落到应用私有目录，作为 `private_copy` 来源；
- 不要假设百度/坚果云客户端会在后台同步某个 SAF 目录；
- 同步任务与阅读分页/索引任务要串行化或分优先级，避免争抢 I/O；
- 同步写库要走现有仓储 API，不要绕过取消/错误模型。

### 7.8 依赖与 ABI 影响（本项目的硬约束）

- 当前五个共享 crate **没有任何网络依赖**（`reading-source` 只有 `encoding_rs`，`reading-storage` 只有 `rusqlite`）。引入同步需要 HTTP/TLS/JSON/XML/哈希等依赖，必须精确锁定版本（`=X.Y.Z`），并检查许可证与 `scripts/verify-core-scope.py`。
- 根 workspace 正式成员固定为 `reading-core`、`reading-ffi`、`reading-index`、`reading-source`、`reading-storage`。新增 `reading-sync` 属于**范围变更**：需要先更新 `scripts/verify-core-scope.py`、设计文档和门禁，不能为了「先跑起来」私自加成员。
- `NR_ABI_VERSION = 1` 是跨语言契约。同步 API 若进入 FFI，需要同时更新 `include/novel_reader.h`、`crates/reading-ffi`、Android JNI/Kotlin 桥接和 ABI 测试；新增函数可以做成加法，但是否升 ABI 版本要按项目裁定，不能静默改布局/语义。
- Android JNI 库是构建产物，必须通过 `scripts/build-android-libs.sh` 重建，不能手工替换二进制。
- 可选实现位置：
  1. **新 crate `reading-sync` + FFI**：跨平台逻辑复用最好，但范围/ABI/依赖变更最大；
  2. **桌面 Rust + Android Kotlin 各自实现传输，共享协议与测试向量**：ABI 不变，但有两份 WebDAV/S3 代码，长期维护成本高；
  3. **阶段 0 只做文件导入导出（无网络）**：不引入网络依赖，先验证合并与数据模型，风险最低。

建议：**先用阶段 0 验证数据模型，再决定是否新增 crate/ABI**；不要在没定范围前直接引入 `reqwest`/`tokio`。

### 7.9 测试清单

必须覆盖：

- 迁移：旧库升级后 `sync_identity`/`content_hash` 正确补齐；不破坏既有数据；备份/回滚；
- 原文件安全：同步、下载、去重、清理、冲突合并后，用户原始 TXT 的 sha256/size/mtime/inode 不变；
- 幂等：同一状态重复合并不产生重复书/书签/分类；
- 冲突：两端同时改进度/书签/分类/删除；验证不丢数据、不产生环、墓碑生效；
- 网络：超时、401/403、429/503、证书错误、半包、302、Range、dlink 过期；
- 原子性：上传中断不留下半个状态；本地下载失败不覆盖旧书；
- 大文件：流式上传/下载，内存不随文件大小增长；
- Android：后台被杀、切换网络、SAF 权限失效、应用私有副本清理后恢复；
- 凭证：退出登录/撤销应用密码后不再发请求；日志无 token；
- 兼容：坚果云/InfiniCLOUD/Nextcloud（至少两家）实际互通；WebDAV `MOVE`/分页差异；
- ABI/头文件：若加 FFI，`verify-abi.py`、`header_parity`、JNI 边界测试全过。

## 8. 风险与合规

| 风险 | 影响 | 应对 |
|---|---|---|
| 平台 API 关停/改版 | 同步突然不可用 | provider-agnostic；本地始终保留完整数据；提供导出包；不把云当唯一副本 |
| 网盘限速/限流 | 首次同步慢、失败 | 元数据优先；批量包；退避；提示换后端 |
| 凭证泄露 | 书库/进度被读取 | 应用密码/子账号最小权限；系统密钥库；可撤销；日志脱敏 |
| 冲突丢数据 | 用户进度被覆盖 | 每设备独立状态文件；墓碑；冲突弹窗；不静默 LWW 删除 |
| 书籍版权/内容审核 | 账号风险/法律风险 | 只同步用户自有文件；默认只同步元数据；不提供分享；告知网盘可见性 |
| 数据出境 | 合规/隐私 | 国内用户默认推荐国内服务；海外服务明确提示 |
| 迁移/回滚 | 升级失败 | 迁移前备份；新表只增不删；迁移测试；失败可回滚 |
| Android 后台限制 | 同步不及时 | 前台同步 + WorkManager；明确「上次同步时间/待同步」状态，不假装实时 |

## 9. 验证计划（落地前必须做）

### PoC-1：WebDAV 两设备（最高优先级）

- 环境：坚果云免费账号 + Linux 桌面 + Android（或第二台桌面）；
- 数据：20 本书（合计约 20 MB）+ 100 条进度/书签；
- 步骤：首次全量 → 第二设备合并 → 两端各改 10 条 → 再同步 → 删除 2 本/2 条书签 → 再同步；
- 记录：请求数/30 分钟、耗时、失败码、冲突结果、原文件哈希是否不变；
- 通过标准：无丢数据、无重复、无环、原文件不变；首次同步不触发长时间 503；冲突可解释。

### PoC-2：百度「个人使用」应用配额

- 创建个人使用应用（限 10 用户），完成 OAuth；
- 连续 24 小时记录：每次请求的 errno、20011/20012/20013、耗时；
- 测试：1 次状态上传/下载、1 本书上传/下载、列目录、断点续传；
- 关键问题：**个人使用模式是否仍是 10 次/小时？** 非会员下载速度多少？dlink 302 是否可跟随？
- 通过标准：若 10 次/小时 → 判定「不适合自动同步」，只保留手动/低频；若频率足够 → 可做可选适配器。

### PoC-3：本地文件夹桥 + 百度同步空间（桌面）

- 把 `.nrsync` 包放进百度同步空间目录；
- 两台桌面（或桌面 + 手动 Android）验证：写入 → 客户端上传 → 另一端下载 → 合并；
- 记录：冲突副本文件名、同步延迟、删除传播、客户端是否锁文件；
- 通过标准：不损坏包、可识别冲突副本、原文件不变。

### PoC-4：对象存储（可选，大书库）

- 七牛云 10 GB 免费额度或 R2 10 GB；
- 1,000 本/5 GB 书库首次同步 + 增量；
- 记录：请求数、流量、耗时、断点续传、内存峰值；
- 通过标准：流式、不 OOM、失败可续、成本在预期内。

### 9.5 常见问题

**Q1：能不能只同步进度，不同步书？**
可以，而且建议默认如此。书籍文件体积大、网盘限速/流量限制主要卡在这里；很多用户各设备本来就有同一份 TXT，只需要同步「读到哪」。把「同步书籍文件」做成显式开关，首次开启时提示预计流量。

**Q2：百度网盘能不能直接当同步盘用？**
桌面端可以：把应用的数据文件夹放进百度网盘「同步空间」，由百度客户端搬运。Android 端不行：百度同步空间不暴露任意可写目录给第三方应用，后台同步也不可控。要跨平台自动同步，需要 WebDAV/API/S3。

**Q3：免费额度够不够？**
只同步元数据：任何免费额度都够。同步书：100–1,000 本、平均 1 MB，约 0.1–1 GB，坚果云免费（每月 3 GB 下载）通常够；5 GB 以上建议 InfiniCLOUD 或对象存储。注意「容量」和「流量/请求数」是两回事。

**Q4：两台设备同时读到不同位置，听谁的？**
不要静默按时间覆盖。同步层保留两台设备的进度记录，检测到「上次同步后两端都改过」时弹窗：继续本机 / 使用云端 / 查看两个位置。若用户选择自动，可按逻辑时钟取新，但仍要在设置里保留「冲突时询问」选项。

**Q5：会不会改坏我的原始 TXT？**
不会。同步只读写应用自己的副本/缓存；原始文件始终只读。任何「清理云端」「删除书架」操作都不删除原始 TXT；删除书籍只写墓碑并保留可恢复窗口。

**Q6：为什么不用 Syncthing？**
它是很好的通用文件同步工具，但 Android 官方应用已于 2024-12 停止，社区 fork 也已归档；把它作为产品内置依赖，长期维护和权限/后台问题不可控。用户自己装 Syncthing 同步一个文件夹，属于「本地文件夹桥」的范畴，可以兼容，但不作为内置实现。

---

## 10. 最终建议（一句话版）

**把「同步」做成 provider-agnostic 的逻辑数据同步：先做可导出/可合并的 `.nrsync` 包验证数据模型，再上 WebDAV（坚果云/InfiniCLOUD/Nextcloud）作为主路线；百度网盘用「本地文件夹桥」兼容桌面，官方 API 只作为个人自用的可选适配器；大书库用七牛/R2/B2/OSS 等 S3 存储。不要同步 SQLite，不要依赖单一网盘 API。**
